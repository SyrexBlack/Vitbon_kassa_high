# Мобильная касса VITBON

## What This Is

Мобильное Android-приложение кассира для розничной торговли, обеспечивающее полный цикл фискальных операций (продажи, возвраты, чеки коррекции, смены, X/Z-отчёты), интеграцию с фискальными регистраторами MSPOS-K и Нева 01Ф, поддержку требований 54-ФЗ, облачный товароучёт, а также опциональные модули маркировки (Честный ЗНАК) и ЕГАИС.

**Соответствие:** 54-ФЗ, ФФД 1.05 и 1.2, Честный ЗНАК, ЕГАИС (с активацией модулей)

## Core Value

Кассир может быстро и безопасно провести продажу/возврат товара с формированием фискального чека и синхронизацией данных — в любое время, в любом месте, онлайн или офлайн.

## Business Context

- **Customer**: Розничные точки продаж (магазины, кафе, киоски), требующие мобильное кассовое решение
- **Revenue model**: Подписка на ПО (ежемесячная оплата тарифа), дополнительная плата за модули маркировки и ЕГАИС
- **Success metric**: Количество успешных фискальных операций без ошибок; uptime приложения
- **Strategy notes**: Облачная синхронизация как основное конкурентное преимущество

### Active

**Базовый функционал (фискальные операции):**
- [ ] **FISC-01**: Продажа товара — сканирование ШК, поиск, ввод веса, скидки, выбор НДС
- [ ] **FISC-02**: Возврат товара — по чеку из БД или QR-коду, выборочный возврат позиций
- [ ] **FISC-03**: Чеки коррекции — приход/расход с текстовым описанием ошибки
- [ ] **FISC-04**: Открытие/закрытие смены — команды через фискальное ядро
- [ ] **FISC-05**: X-отчёт — промежуточный отчёт без закрытия смены
- [ ] **FISC-06**: Внесение/изъятие наличных — отдельные фискальные документы

**Интеграция с ККТ:**
- [ ] **KKT-01**: Поддержка MSPOS-K — печать, статусы, смены, отчёты
- [ ] **KTT-02**: Поддержка Нева 01Ф — печать, статусы, смены, отчёты
- [ ] **KTT-03**: Определение версии ФФД (1.05 / 1.2) при старте и после открытия смены
- [ ] **KTT-04**: Формирование данных чеков в зависимости от версии ФФД
- [ ] **KTT-05**: Запрет переключения версии ФФД на активном ФН

**Товароучёт (облачный):**
- [ ] **GOOD-01**: Локальный справочник товаров — синхронизированная копия для офлайн-продаж
- [ ] **GOOD-02**: Двусторонняя синхронизация REST API — продажи в облако, товары/цены из облака
- [ ] **GOOD-03**: Приёмка товара — документ с отправкой в облако
- [ ] **GOOD-04**: Списание товара — порча, недостача
- [ ] **GOOD-05**: Инвентаризация — сверка остатков, акт расхождений

**Отчётность:**
- [ ] **REPT-01**: Отчёты по продажам — смена/день/неделя/месяц/период, выручка, чеки, средний чек
- [ ] **REPT-02**: Детализация по товарам/категориям
- [ ] **REPT-03**: Отчёт по движению товара — приход, расход, списание, возвраты, остатки
- [ ] **REPT-04**: Отчёт по возвратам — количество, сумма, перечень чеков
- [ ] **REPT-05**: Фискальные отчёты — Z-отчёт, X-отчёт (от фискального ядра)

**Мониторинг статусов:**
- [ ] **MON-01**: Статус интернета — есть/нет, блокировка сетевых операций
- [ ] **MON-02**: Статус облачного сервера — доступен/недоступен, время синхронизации
- [ ] **MON-03**: Статус ОФД — подключение, очередь чеков
- [ ] **MON-04**: Статус модуля Честный ЗНАК — установлен/доступен (опционально)
- [ ] **MON-05**: Статус УТМ ЕГАИС — установлен/доступен (опционально)
- [ ] **MON-06**: Статус оплаты тарифа — активен/просрочен, 7 дней grace period

**Пользователи и администрирование:**
- [ ] **AUTH-01**: Роли — Администратор, Старший кассир, Кассир
- [ ] **AUTH-02**: Аутентификация — пин-код или пароль
- [ ] **AUTH-03**: Журнал действий — audit log, локально + облако
- [ ] **AUTH-04**: Проверка на root — блокировка запуска или предупреждение

**Лицензирование:**
- [ ] **LIC-01**: Проверка статуса оплаты — при запуске и раз в сутки
- [ ] **LIC-02**: Блокировка при просрочке — кроме просмотра отчётов и настроек
- [ ] **LIC-03**: Grace period — 7 дней работы офлайн

**Модуль маркировки (опционально):**
- [ ] **MARK-01**: Сканирование DataMatrix — встроенный сканер или камера
- [ ] **MARK-02**: Валидация через API Честный ЗНАК
- [ ] **MARK-03**: Выбытие маркированного товара при продаже
- [ ] **MARK-04**: Приёмка и возврат маркированного товара

**Модуль ЕГАИС (опционально):**
- [ ] **ALCO-01**: Интеграция с УТМ — настройка адреса, фиксация продажи
- [ ] **ALCO-02**: Вскрытие тары — акт о вскрытии для кег
- [ ] **ALCO-03**: Проверка возраста через Цифровой ID Max — QR-код, API верификация

**Безопасность:**
- [ ] **SEC-01**: Шифрование локального хранилища — учётные данные, товары
- [ ] **SEC-02**: Офлайн-работа — фискальные чеки через ФН независимо от интернета
- [ ] **SEC-03**: Буферизация данных синхронизации при отсутствии связи
- [ ] **SEC-04**: Логирование операций с выгрузкой

**Обновления:**
- [ ] **UPDT-01**: Удалённое обновление приложения

### Out of Scope

- Мобильное приложение покупателя — только кассирское приложение
- Интеграция с платёжными терминалами (эквайринг) — отдельная система
- Desktop-версия приложения
- Windows/macOS/Linux платформы
- Полноценная CRM/ERP система — только товароучёт для кассы
- Офлайн-режим для модулей маркировки и ЕГАИС — требуют онлайн-валидации

## Context

**Техническое окружение:**
- Android 6.0 (API 23)+
- Kotlin + Android SDK
- Фискальные регистраторы: MSPOS-K, Нева 01Ф (SDK производителей)
- Локальная БД для офлайн-работы (Room/SQLite)
- REST API для облачной синхронизации

**Существующий код:**
- Проект Android: `android/` — основное кассовое приложение
- Бэкенд: `backend/` — облачный сервер товароучёта (Kotlin/Spring)
- Документация: `docs/` — e2e-тесты, матрица ФФД, руководства

**Известные ограничения:**
- ФН (фискальный накопитель) — регистрация и замена в фискальном ядре
- API-ключи для облака, Честный ЗНАК, ЕГАИС, сервера лицензий — требуются от заказчика

## Constraints

- **Платформа**: Android 6.0 (API 23) и выше
- **Оборудование**: Планшеты или смарт-терминалы со встроенным/подключаемым принтером чеков и сканером ШК
- **54-ФЗ**: Полное соответствие — фискализация, ОФД, ФФД 1.05/1.2
- **Офлайн**: Фискальные операции работают без интернета; синхронизация буферизируется
- **Модули**: Маркировка и ЕГАИС — активируемые отдельно, без переустановки приложения
- **Root**: Обнаружение root приводит к блокировке или предупреждению

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Kotlin как основной язык | Существующая кодовая база на Kotlin; хорошая экосистема для Android | ✓ Good |
| Room для локальной БД | Надёжность, офлайн-first, реактивность | ✓ Good |
| MSPOS-K и Нева 01Ф | Наиболее распространённые ККТ на рынке РФ | ✓ Good |
| ФФД 1.05 и 1.2 | Соответствие 54-ФЗ, поддержка разных типов ФН | ✓ Good |
| Облачная синхронизация REST API | Стандартный подход, простота интеграции | ✓ Good |
| Опциональные модули | Маркировка и ЕГАИС не нужны всем клиентам, гибкость ценообразования | ✓ Good |

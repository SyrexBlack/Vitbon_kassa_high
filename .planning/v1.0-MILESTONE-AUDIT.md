# Milestone v1.0 — Audit Report

**Milestone:** VITBON Kassovoye Prilozheniye v1.0
**Date:** 2026-06-20
**Status:** ⚠️ **gaps_found** — critical blockers exist

## Executive Summary

The 6-phase structure is complete and most code is in place, but integration checker found **5 critical blockers** that prevent the system from building or working at runtime:

1. **4 missing backend service files** (LicenseService, EgaisService, ChaseznakService, StatusService) → backend won't compile
2. **Missing `createFiscalCore` function** in Android DI → Android app won't compile
3. **`AlcoholSalePolicyUseCase` not wired** into sale pipeline → legal-sensitive alcohol sales not fail-closed
4. **No 500-doc queue cap** in SyncManager → offline queue grows unbounded
5. **No post-fiscal FFD lock** → FFD version can be changed after first document (ФН brick risk)

---

## Critical Gaps (Blockers)

### GAP-01: Missing Backend Services (P0)
**Severity:** CRITICAL — Backend will not compile
**Affected requirements:** LIC-01–03, ALCO-01–05, MARK-01–06, MON-01–06

| Missing File | Referenced By | Impact |
|---|---|---|
| `backend/src/main/kotlin/com/vitbon/kkm/domain/service/LicenseService.kt` | `LicenseController.kt:6,9` | License flow broken |
| `backend/src/main/kotlin/com/vitbon/kkm/domain/service/EgaisService.kt` | `EgaisController.kt:4,10` | EGAIS module broken |
| `backend/src/main/kotlin/com/vitbon/kkm/domain/service/ChaseznakService.kt` | `ChaseznakController.kt:3,9` | Marked goods sales broken |
| `backend/src/main/kotlin/com/vitbon/kkm/domain/service/StatusService.kt` | `StatusController.kt:4,8` | Status indicators broken |

**Evidence:** Stale `.class` files exist in `backend/build/classes/kotlin/main/com/vitbon/kkm/domain/service/{License,Status,Egais,Chaseznak}Service.class` — files were removed from source.

**Fix:** Restore the 4 service files or implement new service classes matching controller constructor signatures.

### GAP-02: Missing `createFiscalCore` Function (P0)
**Severity:** CRITICAL — Android app will not compile
**Affected requirements:** KKT-01, KKT-02, KKT-05, KKT-06

**Evidence:**
- `android/app/src/main/java/com/vitbon/kkm/di/AppModule.kt:28` imports `com.vitbon.kkm.di.createFiscalCore`
- `android/app/src/main/java/com/vitbon/kkm/di/AppModule.kt:124` calls it
- `find android/app/src -name "createFiscalCore*"` → no results

**Impact:** DI graph broken, `provideFiscalCore` provider cannot resolve, tests fail.

**Fix:** Implement `createFiscalCore()` function in `di/` package or remove the import/call.

### GAP-03: `AlcoholSalePolicyUseCase` Unwired (P1)
**Severity:** HIGH — Legal compliance violation
**Affected requirements:** ALCO-01, ALCO-04, vitbon-kassa-1rd.1.3

**Evidence:**
- Class exists at `features/egais/domain/AlcoholSalePolicyUseCase.kt` with fail-closed `UtmStatus` checks
- Never called by `ProcessSaleUseCase`, `MarkedGoodsSaleUseCase`, or `SalePaymentPipeline`
- Alcohol sales would proceed when EGAIS is offline

**Fix:** Wire `AlcoholSalePolicyUseCase.checkCanSellAlcohol()` into `ProcessSaleUseCase.execute()` as a pre-fiscal check.

### GAP-04: No 500-Document Queue Cap (P1)
**Severity:** HIGH — Memory pressure risk
**Affected requirements:** SEC-03, MON-03, Phase C criterion C-4

**Evidence:** `grep -rn "500\|MAX_PENDING" android/app/src` → no results. No cap on `PENDING_SYNC` rows.

**Impact:** Unbounded queue growth when sync fails persistently.

**Fix:** Add queue cap logic to `SyncManager.processCheckPush()` — block new sales or surface warning when PENDING_SYNC > 500.

### GAP-05: No Post-Fiscal FFD Lock (P1)
**Severity:** HIGH — ФН brick risk
**Affected requirements:** KKT-05, vitbon-kassa-1rd (FFD lock)

**Evidence:** `FfdPolicyStore.saveResolved()` exists but no caller invokes it after `executeSale` success. FFD version can theoretically be changed after first fiscal document.

**Impact:** Violates "FFD version is immutable after first document" — could brick ФН.

**Fix:** Add `FfdPolicyStore.saveResolved(version)` call in `FiscalOperationOrchestrator.executeSale()` after success.

# Requirements: VITBON Мобильная Касса

**Defined:** 2026-06-20
**Core Value:** Кассир может быстро и безопасно провести продажу/возврат товара с формированием фискального чека и синхронизацией данных — в любое время, в любом месте, онлайн или офлайн.
**Compliance:** 54-ФЗ, ФФД 1.05 / 1.2, Честный ЗНАК, ЕГАИС

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

---

### 1. Фискальные операции (Fiscal Operations)

- [ ] **FISC-01**: Продажа товара — сканирование ШК, поиск по названию/артикулу, поддержка весового товара, ввод количества/цены/скидки, выбор ставки НДС (18%/10%/0%/5%/7%/без НДС), формирование чека прихода
- [ ] **FISC-02**: Возврат товара — создание чека возврата по чеку из БД или QR-коду, выборочный возврат позиций (поштучно), формирование чека возврата
- [ ] **FISC-03**: Чеки коррекции — приход/расход с текстовым описанием ошибки, ввод номера чека коррекции (автоматически или вручную)
- [ ] **FISC-04**: Открытие/закрытие смены — команды через фискальное ядро, запрет фискальных операций при закрытой смене
- [ ] **FISC-05**: X-отчёт — формирование промежуточного отчёта без закрытия смены (данные по текущей смене)
- [ ] **FISC-06**: Z-отчёт — отчёт о закрытии смены (формируется при закрытии смены)
- [ ] **FISC-07**: Внесение наличных — операция увеличения наличных в ящике, ввод суммы и комментария, отдельный фискальный документ
- [ ] **FISC-08**: Изъятие наличных — операция уменьшения наличных в ящике (инкассация), ввод суммы и комментария, отдельный фискальный документ

---

### 2. Интеграция с ККТ (KKT Integration)

- [ ] **KKT-01**: Поддержка MSPOS-K — печать чеков, получение статусов (ФН, смена, чек), открытие/закрытие смены, X/Z-отчёты, внесение/изъятие
- [ ] **KKT-02**: Поддержка Нева 01Ф — печать чеков, получение статусов, все фискальные операции (делегирование через MSPOS-K сервис)
- [ ] **KKT-03**: Определение версии ФФД — запрос при старте приложения и после открытия смены, сохранение в локальных настройках
- [ ] **KKT-04**: Формирование данных чеков — формирование объекта с разрешёнными полями в зависимости от версии ФФД (1.05 или 1.2)
- [ ] **KKT-05**: Запрет переключения ФФД — приложение не содержит возможности переключить версию ФФД на активном ФН
- [ ] **KKT-06**: Обработка ошибок ККТ — получение и отображение ошибок от фискального регистратора, повторные попытки при recoverable errors

---

### 3. Товароучёт (Inventory Management)

- [ ] **GOOD-01**: Локальный справочник товаров — хранение наименования, артикула, штрихкода, цены, остатка, ставки НДС, группы; офлайн-доступ для продаж
- [ ] **GOOD-02**: Двусторонняя синхронизация — REST API, передача продаж в облако, получение изменений товаров/цен/остатков
- [ ] **GOOD-03**: Приёмка товара — создание документа приёмки на кассе с последующей отправкой в облако
- [ ] **GOOD-04**: Списание товара — документ списания (порча, недостача)
- [ ] **GOOD-05**: Инвентаризация — сверка фактических остатков с учётными, формирование акта расхождений

---

### 4. Отчётность (Reporting)

- [ ] **REPT-01**: Отчёты по продажам — за смену/день/неделю/месяц/произвольный период; показатели: выручка (наличные/безналичные), количество чеков, средний чек
- [ ] **REPT-02**: Детализация по товарам/категориям — количество проданных единиц, сумма
- [ ] **REPT-03**: Отчёт по движению товара — приход, расход (продажи), списание, возвраты, инвентаризация, остатки на начало/конец периода
- [ ] **REPT-04**: Отчёт по возвратам — количество и сумма возвратов за период, перечень чеков возврата
- [ ] **REPT-05**: Фискальные отчёты — Z-отчёт (после закрытия смены), X-отчёт (промежуточный)

---

### 5. Мониторинг статусов (Status Monitoring)

- [ ] **MON-01**: Статус интернета — отображение наличия/отсутствия, блокировка операций требующих сети
- [ ] **MON-02**: Статус облачного сервера — доступен/недоступен, время последней синхронизации, кнопка повтора
- [ ] **MON-03**: Статус ОФД — подключение, передача чеков, количество не переданных чеков
- [ ] **MON-04**: Статус модуля Честный ЗНАК — установлен/не установлен, версия, доступен/недоступен (только если модуль активирован)
- [ ] **MON-05**: Статус УТМ ЕГАИС — установлен/не установлен, доступен/недоступен (только если модуль активирован)
- [ ] **MON-06**: Статус оплаты тарифа — активен/просрочен/нет подключения к серверу лицензий; блокировка при просрочке (кроме отчётов и настроек)

---

### 6. Пользователи и администрирование (Users & Admin)

- [ ] **AUTH-01**: Роли — Администратор (настройка оборудования, товароучёта, управление пользователями), Старший кассир, Кассир (продажи, возвраты, внесение/изъятие, X-отчёт, закрытие смены)
- [ ] **AUTH-02**: Аутентификация — пин-код или пароль
- [ ] **AUTH-03**: Журнал действий — audit log хранится локально и синхронизируется с облаком (actor, deviceId, action, outcome, timestamp)
- [ ] **AUTH-04**: Root detection — проверка на root, блокировка запуска или предупреждение (soft warning, ≥2 indicators для блокировки)

---

### 7. Лицензирование (Licensing)

- [ ] **LIC-01**: Проверка статуса оплаты — при запуске приложения и периодически (раз в сутки)
- [ ] **LIC-02**: Блокировка при просрочке — все операции заблокированы кроме просмотра отчётов и настроек; сообщение о необходимости оплаты
- [ ] **LIC-03**: Grace period — 7 дней работы после последней успешной проверки при отсутствии интернета (вычисляется от expiresAt, не от lastCheck)

---

### 8. Безопасность (Security)

- [ ] **SEC-01**: Шифрование локального хранилища — SQLCipher 4.5.4 + Room SupportFactory + Android Keystore для ключей
- [ ] **SEC-02**: Офлайн-работа — фискальные чеки печатаются через ФН независимо от интернета
- [ ] **SEC-03**: Буферизация синхронизации — данные для облачной синхронизации буферизируются при отсутствии связи и отправляются при восстановлении
- [ ] **SEC-04**: Логирование операций — продажи, ошибки, статусы с возможностью выгрузки
- [ ] **SEC-05**: TLS mutual authentication — для защищённого соединения с облаком

---

### 9. Обновления (Updates)

- [ ] **UPDT-01**: Удалённое обновление — поддержка remote update механизма

---

### 10. Модуль маркировки — Честный ЗНАК (опционально)

> Требует отдельной активации. Без активации функции маркировки недоступны.

- [ ] **MARK-01**: Сканирование DataMatrix — встроенный сканер или камера, валидация через API Честный ЗНАК
- [ ] **MARK-02**: Проверка кода — в обороте, не выбыт, срок годности не истёк; онлайн-валидация (офлайн для маркированных товаров НЕ поддерживается)
- [ ] **MARK-03**: Выбытие маркированного товара — при продаже, групповое выбытие нескольких единиц в чеке
- [ ] **MARK-04**: Обработка ошибок валидации — блокировка продажи до исправления
- [ ] **MARK-05**: Приёмка маркированного товара — через сканирование кодов
- [ ] **MARK-06**: Возврат маркированного товара — оформление возврата с повторным вводом кода в оборот

---

### 11. Модуль ЕГАИС (опционально)

> Требует отдельной активации. Без активации продажа алкоголя невозможна.

- [ ] **ALCO-01**: Интеграция с УТМ — настройка адреса локального УТМ, фиксация розничной продажи алкоголя (включая пиво в кегах)
- [ ] **ALCO-02**: Вскрытие тары — акт о вскрытии при продаже из кег
- [ ] **ALCO-03**: Проверка возраста — сканирование QR-кода с Цифрового ID Max, отправка запроса в API Max, получение результата (подтверждён/не подтверждён)
- [ ] **ALCO-04**: Блокировка продажи — при неподтверждённом возрасте продажа алкоголя блокируется
- [ ] **ALCO-05**: Логирование — дата, результат проверки, ID проверки возраста

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Расширенная синхронизация

- **SYNC-01**: Batch sync для 200+ касс — Redis Streams backend для массовой ингаляции чеков
- **SYNC-02**: Conflict resolution — server-wins по timestamp для двусторонней синхронизации

### Дополнительные интеграции

- **EXT-01**: Интеграция с эквайрингом — поддержка платёжных терминалов (отдельная система)
- **EXT-02**: Другие модели ККТ — расширение списка поддерживаемых фискальных регистраторов

### Аналитика

- **ANLY-01**: Dashboard — визуализация ключевых показателей для администратора
- **ANLY-02**: Прогнозирование — прогноз спроса на основе истории продаж

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Приложение покупателя | Не входит в ТЗ — только кассирское приложение |
| Интеграция с эквайрингом | Отдельная система — платёжные терминалы |
| Desktop-версия | Только Android (мобильные устройства) |
| Windows/macOS/Linux | Не предусмотрены ТЗ |
| Полноценная CRM/ERP | Только товароучёт для кассы (синхронизация с облачным сервером) |
| Офлайн для маркировки | Требует онлайн-валидации; офлайн-режим не поддерживается |
| Офлайн для ЕГАИС | Требует онлайн-валидации через УТМ |
| Ручной ввод без ККТ | Все операции через фискальный регистратор |
| ФФД 1.0 | Не поддерживается (только 1.05 и 1.2) |
| Root/jailbreak bypass | Безопасность — блокировка или предупреждение |

# VITBON Kassovoye Prilozheniye — Features Analysis

**Дата:** 2026-06-20
**Статус:** Исследовательский документ
**Потребитель:** Определение требований (requirements definition)

---

## Обзор

Документ анализирует функциональность Android-приложения кассира VITBON для розничной торговли (54-ФЗ). Категоризация построена на:
- Техническом задании (ТЗ) проекта
- Архитектурной спецификации (`2026-04-08-vitbon-kkm-design.md`)
- Руководствах администратора и кассира
- Общей функциональной модели

---

## Условные обозначения сложности

| Уровень | Обозначение | Описание |
|---------|-------------|----------|
| Низкая | 🟢 | Реализуется в рамках существующих модулей |
| Средняя | 🟡 | Требует новой интеграции или API |

## 3. ANTI-FEATURES (Сознательно НЕ строим)

> **Критерий:** Функции, которых следует избегать — либо по стратегическим причинам, либо из-за технической/юридической нецелесообразности.

| ID | Анти-фича | Причина |
|----|-----------|---------|
| AF-01 | Мобильное приложение покупателя | Фокус на B2B-кассирском приложении; отдельный продукт |
| AF-02 | Интеграция с платёжными терминалами (эквайринг) | Отдельная система; не входит в scope |
| AF-03 | Desktop-версия приложения | Android-only по ТЗ |
| AF-04 | Windows / macOS / Linux платформы | Android-only |
| AF-05 | Полноценная CRM/ERP система | Только товароучёт для кассы, не полный бэкенд |
| AF-06 | Офлайн-режим для модулей маркировки и ЕГАИС | Требуют онлайн-валидации (54-ФЗ, Честный ЗНАК) |
| AF-07 | Поддержка других ККТ (кроме MSPOS-K, Нева 01Ф) | Расширение списка — отдельная задача |
| AF-08 | ФФД 1.0 (устаревший) | Не поддерживается — только 1.05 и 1.2 |
| AF-09 | Поддержка Android ниже 6.0 (API 23) | Устаревшие устройства — за пределами поддержки |
| AF-10 | Ручной ввод фискальных данных без ККТ | Нарушение 54-ФЗ |
| AF-11 | Отключаемый ФН (фискальный накопитель) | Обязателен по законодательству |

## 5. ДОПОЛНИТЕЛЬНЫЕ ЗАМЕЧАНИЯ

### 5.1 Критический путь

1. **FiscalCore** → основа для всех фискальных операций (TS-*)
2. **Room/SQLite** → локальная БД → офлайн-работа (TS-20)
3. **WorkManager sync** → облачная синхронизация (D-01)
4. **Backend API** → товароучёт, отчёты (D-10, D-20)
5. **Модули (ЧЗ, ЕГАИС)** → активируются после стабилизации core

### 5.2 Риски реализации

| Функция | Риск | Мера снижения |
|---------|------|--------------|
| D-30..D-34 (Маркировка) | Изменение API Честный ЗНАК | Feature flag, абстракция API |
| D-40..D-43 (ЕГАИС) | Изменение формата УТМ | Feature flag, изоляция модуля |
| D-04 (200+ касс) | Конфликты синхронизации | Redis Streams, server-wins |
| TS-08 (ФФД 1.05/1.2) | Изменение требований 54-ФЗ | Модульное формирование ФД |

### 5.3 Порядок реализации

```
Этап 1: Table Stakes Core
  → TS-01..TS-08 (фискальные операции)
  → TS-10..TS-13 (интеграция ККТ)
  → TS-20..TS-22 (офлайн)
  → TS-30..TS-33 (аутентификация)
  → TS-40..TS-42 (лицензирование)
  → TS-50..TS-53 (мониторинг)

Этап 2: Table Stakes Reporting
  → D-20..D-23 (отчётность)

Этап 3: Differentiators — Cloud
  → D-01..D-05 (синхронизация)
  → D-10..D-13 (товароучёт)

Этап 4: Differentiators — Modules
  → D-30..D-34 (маркировка)
  → D-40..D-43 (ЕГАИС)
  → D-50..D-52 (безопасность)
```
